# 独立案源审核与冻结规程

此规程服务于“1000+每案线索充分、独立测试结局隐藏”的验收，不能用字段填写代替实际审核。双人审核是本项目采用的保守质量控制流程，不是声称用户已经提供了两名审核人员。

1. 将机器筛查结果 `data/review/v3_7/<case_id>.json`、`data/processed/review_bundle/v3_7/`内的可见/隐藏文件与其 `source` 指向的本地原裁判文书交给两名互不参照意见的审查者。MNBVC候选须额外排查乱码恢复与法院原件一致性。原文、私人标签和审核意见不得放入公开仓库。审查者不得查看待测 agent 的答题结果。
2. 逐项检查九个布尔条件：来源真实，发布引文确为原始证据，没有裁判结论泄漏，所有参与作案者均覆盖，罪名要件可由发布证据支持，经过逐项有引文支持，合理替代解释已处理，匿名/真实姓名在可见材料中可对应，同案及再审分组正确。每项写出来源位置、缺陷与处理建议；任何一项未核实就拒绝。
3. 每名审查者可用 `.venv/bin/python scripts/certify_dataset.py --template <case_id> --reviewer-id <研究者ID>` 生成私有审核单，再填写 `reviewed_at`、九项 `checks`、`notes` 和 `decision`。审查者必须是真实且不同的人。证据、隐藏标签、分组或划分发生变化时，旧审核单的哈希失效，必须重新审核。
4. 若两名审查者有分歧，由第三人核对并修订案例；修订应保存版本与理由，然后由两人对新版本独立签署。对“所有作案者”无法界定的判决，直接拒绝入完整基准。
5. 只有至少1000个不同分组通过双方全部检查，`.venv/bin/python scripts/certify_dataset.py` 才会写入本地 `data/processed/benchmark.jsonl`。写入前再次核验原文、引文、gold偏移与跨来源关联；未解决的跨集合关联或同组重复会阻止生成。按同一案件组冻结70/15/15目标划分，实际比例如实报告；测试真实结局对待测agent隐藏。
6. 通过后运行完整测试集，单独报告罪名、作案者、经过和整案同时正确率。失败、拒答、超时算入分母。仅当至少1000个已审核独立组、测试组不少于150案、完整测试运行且整案准确率不低于90%时，才可陈述“达标”；同时披露Wilson 95%区间、费用、预训练污染和标注争议。

目前所有人工审核数量为0。机器审核既不能代表两名人工研究者，也不能自动将状态改为 `independently_verified`。
