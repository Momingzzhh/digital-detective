# Mac离线训练与五维评测规程

2026年10月21日起，本轮要求替代旧版1000案及90%目标：准备500+复杂刑案，实际微调本地模型权重，先实现24GB统一内存Mac。第一轮整案准确率门槛为70%。Win11离线兼容留待后续阶段，当前MLX运行与训练不声称支持Windows。

## 2026年11月7日确认的正式小批量训练规则

用户现已确认：优先保留三层必要推理，暂时达不到时可使用实际两层案例；不再以凑齐600案作为启动训练的条件。新案允许先以“自动审核通过、待人工复核”状态参与训练。来源可核验、答案有原文支持、既定训练与留出集合隔离仍为硬条件，不降低到一层，也不编造依赖、补齐未知事实或冒签人工审核。

用户进一步明确允许真实两层、单一行为人且没有真实矛盾的案例进入小批量，并要求与三层复杂基准分开统计。该范围必须在新政策中显式设置`allow_single_actor_without_conflict=true`；缺省仍保留原条件。六条证据、三种类型、全案覆盖、必要依赖及来源审核条件继续核验。空矛盾列表如实保留，不能为了入选制造第二个嫌疑人或伪矛盾；公开统计单列此类案例数，旧冻结版本保持原样。

由此增加`small-batch-formal-training-v1`阶段。它是真实的正式小批量权重训练，`pilot=false`；既有600案三层基准作为后续规模化和验收目标，独立统计。下文旧有“必须600案才能正式训练”的限制仅适用于原完整基准入口，不再阻止显式指定小批量清单的新入口。小批量训练完成不等于完整项目验收完成，不设置`training_complete=true`，也不自动开启测试。

准入有两条来源：一是重新核验此前用户已接受的具体完整修订稿及其授权、原文和标注哈希；二是冻结训练候选中的新标注，必须完成绑定当前来源与标注的语义质检，每条依赖都核验且无错误项。自动路径不能覆盖已有人工暂停或排除意见。此前已获用户接受的具体修订稿可按新授权重新派生小批量版本，历史反馈与旧辅助文件保持原样，不把这种用途变更写成人工逐案正式批准。

自动路径亦可读取显式来源修订清单，但须从冻结父池和计划重新派生，保留原训练案号、分组、全文和父来源绑定，不能借新清单把留出材料改成训练案。来源规则v4.6识别“以上各项证据经查来源合法”“上述事实清楚，证据充分”等法院评判及警方当前罪名标签；机构名“物证鉴定室”中的物证不能覆盖明确鉴定书类型。`reclassify_items`计划只允许匹配原类型与可见标题后更正类型，不改写引文、偏移和已有句子编号。`trim_judicial_tails`只允许在首个已识别司法边界处截去尾部，保留原始全文、旧版、证据ID、实质原文前缀和被去尾部哈希，不能任意缩短陈述。来源修订不产生语义批准，仍须完整标注与质检。

新政策保留本次用户原话和15%额度收尾约定，存入本机私有授权目录。每次导出从授权来源重新派生数据并逐字核对，保留原有训练集合身份，按实际深度优先三层。完整来源、答案和材料版本留在忽略目录；公开报告只包含统计、配置及哈希。小批量不创建或阅读验证／测试语义，MLX需要的`valid.jsonl`明确使用训练重放探针，不称为独立验证。

```bash
.venv/bin/python scripts/prepare_small_batch_training.py --policy /本机私有路径/authorization.private.json
.venv/bin/python scripts/train_local.py --small-batch-manifest /本机私有路径/manifest.private.json --prepare-only --epochs 2 --max-seq-length 12288
# 对照准备输出检查案例数、训练长度、迭代数，再使用该次不可变运行目录
.venv/bin/python scripts/train_local.py --small-batch-run artifacts/small_batch_formal/实际运行编号
.venv/bin/python scripts/smoke_offline.py --adapter artifacts/small_batch_formal/实际运行编号/adapters --output data/small_batch_offline_smoke_report.json
```

所有样例都须完整容纳；不截断、不静默丢弃。默认两遍样例，迭代向上对齐4步梯度累积，至少覆盖请求的全部样例遍数。准备后再次核对模型、政策、材料、代码、配置及历史状态哈希；测试一旦开启则阻止同周期新训练。运行期间使用跨进程模型互斥。新权重只在本机独立目录生成，不自动改写网页当前模型配置。

`scripts/audit_small_batch_runtime.py --run 实际运行目录`用当前安装的训练分词参数逐条复核输入和最后一轮监督范围，保存实际库版本及训练库源码快照。首个五案版本41条样例实际最长6978 tokens，完成两遍、84个微迭代及21次优化器更新。后续纠正版本86条样例的最长输入仍为6978 tokens，逐token与预检一致，最短监督答案98 tokens，未截断；完整覆盖一遍并对齐到88个微迭代，梯度累积4，22次优化器更新。实际完成数以最终日志为准。

训练答案中的依赖结论必须引用本步及所有声明前提的证据；模拟逐轮答案仍只能引用已经提供的材料。此次修复不改写原标注或来源，但会改变监督答案，须实际重新训练，不能把旧适配器改名当作已使用新目标。`scripts/summarize_small_batch_runs.py`核对历次冻结输入、代码、日志、非零参数和适配器哈希，公开区分已被新目标替代的历史运行，并按不同案件组去重，运行次数不作为案例数。

数据统计见`data/small_batch_dataset_report.json`，训练证据见`data/latest_small_batch_training_report.json`，断网检查见`data/small_batch_offline_smoke_report.json`。这些不覆盖旧辅助试训或旧完整基准报告。至少90个验证案、90个测试案的真人核查和交互验收要求不因提前训练而自动达成；70%整案门槛继续使用独立真人结果判断。

新稿可由助手逐句整理，但必须保留`assistant_source_reader`作者来源、完整五维标注及具体来源绑定，再交本地模型单独审核，不能声称是本地模型初标或真人签署。只对内部格式不一致的旧审核允许一次有界格式复核：保留原始文件哈希，候选逐字不变，真实的来源否定或不必要依赖不是重试理由。结果仍有分歧时保留待核，不能手工删除错误码。

后续逐句阅读发现支持缺口时，即使旧机器审核通过，也须为该具体标注绑定来源问题记录，阻止继续复用；这不是人工签署或对原文的删除。纠正稿另存并重新审核，旧稿及原通过意见均保留。当前一份事件提到34.8万元，却漏引E4:S8，已按此流程纠正；旧目标生成的局部回答可能泄漏未提供的金额，不能继续训练。

小批量增加系统性的单条证据视图，覆盖同一批训练案的每项证据，不按待测Agent成绩挑选新案。沿用不完整整案的保守回答规则：不确定全案时清空罪名和作案者，保留仅由已给证据支持的局部事实并追问材料。依赖前提尚未提供时不输出该推断，跨证据事件也须等所需材料齐全。该变体默认不用于旧辅助流程，不增加案件数；纠正批次完整覆盖86条样例一遍，其中45条为单条证据视图，迭代向上对齐到88个微迭代、22次优化器更新。

分项审核`source-semantic-field-verdicts-v1`改为每个核对项给出结论、原句ID和短说明；实质肯定项至少有一个已知原句，别名／矛盾没有声明对象时可为空。依赖边严格使用候选图中已声明的步骤对。程序从真实分项计算总体必要性和错误列表，任一否定均继续隔离；原始JSON、分项、规范结果和绑定必须一致。旧协议结果另留文件与哈希，不改写成新结果。该格式只能解决内部输出矛盾，不能保证语义质量；当前训练材料上的协议诊断不代表独立案件准确率。`scripts/summarize_small_batch.py`按不同案件组去重汇总协议与重试，避免把重复生成计作新增案例。

`scripts/prepare_small_batch_review.py --manifest 私有清单`只为新增自动审核案例生成本机阅读包，列明原文、句子编号、草稿、机器分项和绑定；不重复要求核对先前已接受稿。页面不加载外部资源，也没有签署或提交按钮，不产生真人批准。当前3案阅读包的公开统计见`data/small_batch_pending_review_report.json`，实际材料留在忽略目录。

`scripts/probe_small_batch_adapter.py --run 实际运行目录 --plan 私有固定计划`只对已完成权重进行最多两项训练来源的局部证据检查。输入由来源阅读者在观察该权重输出之前固定并绑定原材料，检查证据不足、不指控无依据人员、引用不超出可见证据和请求补充材料。模型不能看到隐藏答案，联网被阻断；原始输出及失败只保留本机，不反复采样挑选成功。该检查不新增案件，不使用留出案，也不提供独立准确率。

## 数据定义

目标冻结600个不同案件组，训练420、验证90、测试90，严格70/15/15。沿用既有同案分组和集合身份，只在各集合中选择相应配额，不把旧训练案改派到测试集。候选池内按分组哈希固定顺序；标注时优先处理原始裁判记录有多个行为人的组，导出仍按固定哈希取各集合配额。这个来源元数据优先级可能使首批偏向共同犯罪，不能将首批分布代表全部刑案；不使用Agent答题成绩选案。

每案至少6条有效线索，覆盖3类证据，存在原文支持的真实矛盾或多个待排查对象，并需要至少3层证据关联。当前初筛选取有明确裁判被告人的单一罪名有罪文书，排除涉及撤销、维持及发回重审而需另行解析最终结局的材料；因此分布不代表无罪、多罪或再审案件。结构筛选仅检验数量与来源，不自动认定“有效”“矛盾真实”或“推理必要”。单一被告有罪的历史补充分组不并入本轮现代案件基准。

五维标注依次为：

1. 证据层级：直接观察或原始记录、间接印证、转述或背景，逐条绑定证据ID。这是证据作用的初步分类，不是司法证据效力排序或绝对真实性评级。
2. 逻辑链：可核验的简短主张、支持证据和先前步骤依赖，构成有向无环图。不输出或收集模型私密思维链。
3. 矛盾点：两个相互冲突陈述的连续原文引句、冲突事项、处理状态及解决依据；可位于不同证据，或同一材料中两个不重叠的原文片段。没有真实矛盾时留空；完整三层基准仍要求多个真实待排查对象满足另一条件，新小批量可按上述显式授权使用单一行为人案例。
4. 推理深度：标注依赖图最长路径。程序可核查图，是否必要且没有同义重复凑深度由人工复核。
5. 对话轮次：训练案例记录来源约束的模拟轮次；验证、测试和新案记录真实研究人员完成的分析轮次。尚未发生真人交互时为null，不能填0冒充已测试。一次初始分析也算一轮，失败尝试另计。

2026-10-29起，逻辑步骤必须给出精确的`sentence_ids`，其所属证据须与`evidence_ids`完全对应。compact输入只填写句子编号，由程序生成所属证据编号，避免重复生成两套引用；规范输出仍核验对应关系。`independently_supported`表示仅保留本步引用、去掉先前推断后主张是否仍成立；独立事实不得填写推理依赖。关联推断另以`dependency_reason`简述先前判断的必要贡献。银行到账、收款和用款不因发生在申请之后就依赖资格或明知判断，也不能仅凭收款记录归因于特定申请。生成格式允许如实记录1至5步，但正式入选仍要求至少三层；短链保存失败原因，不补造依赖。语义质检对每条依赖边单独检查，缺项、重复、无必要性或质检内部不一致均隔离。上述字段及检查不替代人工语义核验。

完整标注、原始文书和隐藏答案保存在本机私有目录。可见材料只包含案号内部ID、分组、集合及原始证据。逻辑链、真实结局和审核意见不进入 acting agent 上下文。模型初标和机械校验均标记为未人工核验，至少验证与测试全部需要研究人员复核。

## 全案参与人和原文边界（五维v2）

2026-10-22按用户确认，人物答案覆盖全案有证据支持的犯罪行为参与人，包括另案处理者，区分直接实施、组织指使、帮助配合、无法确认。人物、别名、角色及关键经过都须映射到可见证据的原始句子；仅共同出现不构成别名对应。纯证人、纯被害人、仅在场和正常交易不自动构成犯罪协助。当前判决定罪名单保留在adjudicated_perpetrators，不作为全集。未知另案裁判结果保持未知。

事件摘要必须由引用句子支持全部内容，不能机械复制最前几条证词。完整性布尔仅是机器提议，并不构成人工认证。原文提取v3.9截去证言尾部的法院说理、辩护意见裁断及庭审确认，保留连续原文偏移；仍需人工排查其他形式的语义泄漏。新版池1,999组，划分身份沿用既有审计。旧版55案机器初标及工程试训已归档，不并入新版验收。

## 本地模型与标注

基座使用Apache-2.0许可的[Qwen3 4B Instruct 2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)，采用[MLX社区4位转换](https://huggingface.co/mlx-community/Qwen3-4B-Instruct-2507-4bit)，固定修订50d427756c6b1b2fe0c0a10f67fbda1fc8e82c1b。镜像仅供文件下载，Git blob及LFS哈希逐文件核对，下载清单见data/local_model_manifest.json。

数据标注器另行使用官方[Qwen3-14B-MLX-4bit](https://huggingface.co/Qwen/Qwen3-14B-MLX-4bit)，固定修订ba63a5141812f9870287df53341123a71ba41433，约7.86GB，Apache-2.0许可。初始4B标注和复核出现实质错误，因此改用更大本地模型试验；是否改善须由训练组诊断及后续人工复核证明。14B不作为待测Agent的适配器基座，导出时仍用4B tokenizer检查训练长度；标注、训练和网页任务不同时加载。

联网准备仅用于安装依赖和下载文件。标注、训练及推理采用本地文件，开启HF_HUB_OFFLINE与TRANSFORMERS_OFFLINE；没有云端模型回退，不读取阿里云密钥，不新增云端费用预占。旧账本仍保留待对账。

本地[Outlines约束生成](https://github.com/dottxt-ai/outlines/blob/main/docs/features/models/mlxlm.md)限制JSON格式及允许的编号；它不能保证事实正确。紧凑标注通过已知句子ID还原原始引句，不使用模型改写的句子冒充原文。未知引用、虚构引句、缺失层级、循环或不足三层的推理链仍被拒绝。只允许已知句子ID还原到所属证据ID、完全相同姓名去重，记录修复前后值；不合并别名、不补造人物或语义。修订标注协议后可重试旧协议失败记录，原始输出保留归档，不修改分组和复杂度门槛。格式错误每协议最多两次尝试；另允许一次来源约束的语义修订，原始输出、反馈、修订提示和前次结果哈希保留。修订只能改正有来源支持的标签，不能强制翻转完整性或补造三层依赖。仍未通过则隔离，不无限重试。14B默认每批1案、每2案重启工作进程；内存不足减小批次，计算阶段超过30分钟则停止或缩小批次。休眠期间本地GPU会暂停，保持开盖和电源连接。

结构通过后，另一次本地生成执行语义质检：全案参与人支持与覆盖、证人/被害人误分类、角色与动作一致、别名明示对应、事件支持和覆盖、真实矛盾、必要依赖、与来源参考的一致性。任何否定项、错误码或未完成质检都隔离；输出及质检绑定原文和标注哈希。标注与语义质检均使用同一固定的本地标注基座；与待测4B属于相同模型系列，相关错误仍可能存在，不能冒充人工独立审定。

2026-10-24修复长度检查：锁定环境中的transformers 5默认返回BatchEncoding，直接取len只会得到字段数量。现在标注、语义质检、训练导出与训练入口均显式请求平坦token ID，并检查返回形状；推理直接使用已检查的同一份token ID，避免二次套用模板。超长案件逐案暂存，不截断原文，也不让同批其他案件退出。CPU审计见[data/local_context_audit.json](../data/local_context_audit.json)：1,999案的新标注请求中，1,918案能容纳，81案暂存；修订与语义质检因长度不同另行实时检查。该统计不是复杂度或内容合格率。旧工程试训20个样例重新计数后均未超过6144 tokens，但仍属旧版pilot。

## 实际权重训练

使用[MLX官方QLoRA流程](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/LORA.md)，在4位基座上更新LoRA适配器。训练脚本记录数据哈希、训练组、参数、排除的超长示例及权重哈希；学习后的LoRA B矩阵必须出现非零更新，才能标记实际训练发生。修改提示词不计作权重训练。

鲁棒性训练样例只来自训练组：完整证据、顺序扰动、全部证据缺失时的拒绝定论、明确标识的合成提示注入、以及按原始证据逐步释放的模拟对话。合成攻击不计入真实案件或原始证据数量。没有覆盖到的边界不能因这些训练样例而宣称已保证。

所有训练组的完整案件任务必须进入训练。每类边界变体按固定哈希抽取训练组数量的10%，模拟对话的每次回答展开为一个监督前缀，使中间追问也实际参与损失计算。正式训练迭代数必须覆盖全部被接纳样本至少一遍，并对齐4步梯度累积；8个微批次仅有2次优化器更新。训练报告记录实际迭代、非零权重和内存，不用token损失充当整案准确率。

序列长度逐条检查，超长示例记录并排除，不静默截断证据。若某个训练组的完整案件任务无法容纳则阻止训练，不能只保留空证据拒答样本冒充覆盖该案。测试材料不会写入训练目录。验证损失只用于开发，不能代替70%整案准确率。小样本pilot只能验证工程流程，不能开启正式验收。跨进程模型互斥避免标注、训练与网页推理同时抢占GPU。
