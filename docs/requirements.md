# 需求及验收口径

本文件基于用户逐项确认及本地 PPT / Word 内容整理。用户的后续确认优先于开题材料中的早期方案。

| 项目 | 当前约定 |
| --- | --- |
| 用户 | 研究人员；支持新案件输入和上传 |
| 交付 | 中文网页、完整后端、本地可运行、部署配置、Momingzzhh 的公开 GitHub 仓库 |
| 部署 | 先在 M5 MacBook Air 运行；本次不部署公网 |
| 模型 | 北京百炼 Qwen3.8-Flash；所有原 Kimi 接口替换；API 总预算不超过 500 元 |
| 数据 | 至少 1000 个真实刑事案件，每个案件关键证据必须在公开原始材料中找到依据 |
| 地域 | 优先中国大陆，确实不足时可采用国外公开案件并提供中文分析 |
| 构建 | 可生成提问、释放线索的方式与明确标注的干扰项；不能补造决定性证据 |
| 输入 | 文字案情和鉴定结果；不直接识别原始指纹、DNA、视频 |
| 结果 | 罪名判断、作案者识别、关键经过还原；允许证据不足与继续追问 |
| 目标 | 最终结论准确率 90%；分别评测各项，不把罪名准确率当破案准确率 |
| 测试 | 独立案件测试、隐藏结局、未用于下游训练；如实报告失败，不预先保证达标 |
| 分发 | 源许可不允许重发的原文保留本地，公开代码/索引/处理脚本/可公开标注 |

## 与开题方案的对应

开题 PPT 的五个模块对应：证据感知（原文提取及定位）、矛盾检测（结构化冲突与复核）、推理规划（有界工具决策）、证据图谱（证据/人物/结论关系）、对话推理（多轮材料与提问）。

“认识 A、A 认识 B”不推出“认识 B”；图谱中的“提及”只表示原文提及，不自动推断事实成立。无独立训练数据及 GPU 的当前版本不声称实现或训练了独立 NLI、NER、Sentence-BERT 模型，相关任务通过 Qwen 结构化调用和程序验证实现。

PPT 提及的 CoT/ToT、RAG、Neo4j 是技术方案参考，不是准确率证明。第一版采用明确的工具步骤、竞争假设及独立复核，用 SQLite 保存状态、网页展示图谱，不以暴露模型内部思维链替代解释。未实现的框架或对照实验不会标记为完成。

每案 20+ 证据节点与 5–10 轮交互是开题设计期望；不能为了凑节点/轮次编造证据。实际按原文可用证据与提问需求记录，数量分布应在数据报告中给出。

五维标注（证据层级、逻辑链、矛盾点、推理深度、对话轮次）需要有来源支持且区分机器与人工。未具备的维度必须记为待审核，不能用固定常数伪装标注。

## 不能混淆的指标

1. 原始文书数量 ≠ 通过来源、泄漏与证据充分性检查的案例数量。
2. 机器审核通过 ≠ 人工确认充分性；两次相同基础模型调用可能存在相关错误。
3. 本案判决中被定罪者集合 ≠ 文本中所有参与者；另案处理、证人、被害人不能混算。
4. 机器辅助经过评分 ≠ 经独立法律专家复核的结论准确率。
5. 未参与下游训练 ≠ 未出现在基础模型的预训练语料。

## 正式验收

数据集、实验和系统分别验收。只有数据质量、结论口径及测试独立性均得到确认，才可将测试结果作为 90% 目标的有效证据；任何缺口需保留在最终说明中。
