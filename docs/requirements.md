# 需求及验收口径

本文件基于用户逐项确认及本地 PPT / Word 内容整理。用户的后续确认优先于开题材料中的早期方案。

| 项目 | 当前约定 |
| --- | --- |
| 用户 | 研究人员；支持新案件输入和上传 |
| 交付 | 中文网页、完整后端、本地可运行、部署配置、Momingzzhh 的公开 GitHub 仓库 |
| 部署 | 先实现24GB统一内存的Apple Silicon Mac离线运行；Win11离线兼容为后续阶段；本次不部署公网 |
| 模型 | 停止所有外部模型API；使用本地Qwen3 4B四位Agent基座及实际训练的LoRA适配器；数据整理可单独使用本地14B模型；旧API账本仅保留待对账 |
| 数据 | 500+复杂真实刑案；当前工程目标600个独立案件组，420/90/90严格70/15/15；原始线索必须有来源 |
| 地域 | 优先中国大陆，确实不足时可采用国外公开案件并提供中文分析 |
| 构建 | 可生成提问、释放线索的方式与明确标注的干扰项；不能补造决定性证据 |
| 输入 | 文字案情和鉴定结果；不直接识别原始指纹、DNA、视频 |
| 结果 | 罪名判断、全案有证据支持的行为参与人（含另案处理者）及其角色、关键经过还原；允许证据不足与继续追问 |
| 目标 | 第一轮整案准确率不低于70%；罪名、全案行为参与人、角色、关键经过均正确才计整案正确 |
| 测试 | 独立案件测试、隐藏结局、未用于下游训练；如实报告失败，不预先保证达标 |
| 复杂度 | 至少6条有效线索、3类证据，真实矛盾或多个待排查对象，至少3层必要证据关联；程序图深度不能替代语义复核 |
| 训练 | 真正更新权重；鲁棒性边界样本只能由训练组生成；训练阶段不使用真人交互 |
| 真人交互 | 用于最终实现、完整验证/测试和后续新案；至少验证、测试案源及标注须由研究人员核验 |
| 分发 | 源许可不允许重发的原文保留本地，公开代码/索引/处理脚本/可公开标注 |

## 与开题方案的对应

开题 PPT 的五个模块对应：证据感知（原文提取及定位）、矛盾检测（结构化冲突与复核）、推理规划（有界工具决策）、证据图谱（证据/人物/结论关系）、对话推理（多轮材料与提问）。

“认识 A、A 认识 B”不推出“认识 B”；图谱中的“提及”只表示原文提及，不自动推断事实成立。当前使用本地结构化生成、证据工具和来源校验；不声称额外训练了独立NLI、NER、Sentence-BERT模型。

PPT 提及的 CoT/ToT、RAG、Neo4j 是技术方案参考，不是准确率证明。第一版采用明确的工具步骤、竞争假设及独立复核，用 SQLite 保存状态、网页展示图谱，不以暴露模型内部思维链替代解释。未实现的框架或对照实验不会标记为完成。

每案20+证据节点与5–10轮交互是开题材料的早期设计期望。本轮按用户后续确认的复杂度门槛执行，不能为了凑节点、逻辑层数或轮次编造内容。模拟训练轮次与观察到的真人轮次必须分开。

五维标注（证据层级、逻辑链、矛盾点、推理深度、对话轮次）需要有来源支持且区分机器与人工。未具备的维度必须记为待审核，不能用固定常数伪装标注。

## 不能混淆的指标

1. 原始文书数量 ≠ 通过来源、泄漏与证据充分性检查的案例数量。
2. 机器审核通过 ≠ 人工确认充分性；两次相同基础模型调用可能存在相关错误。
3. 本案判决中被定罪者集合 ≠ 文本中所有参与者；另案处理、证人、被害人不能混算。
4. 机器辅助经过评分 ≠ 经独立法律专家复核的结论准确率。
5. 未参与下游训练 ≠ 未出现在基础模型的预训练语料。

## 正式验收

数据集、实验和系统分别验收。完整验证集通过70%后才开启冻结测试集；失败、超时、拒答和未完成案均保留在分母。真实训练、至少验证/测试来源人工复核、完整验证与最终测试全部通过后才标记完成。详细流程及尚未通过项目见[本地训练规程](local_training_protocol.md)和[data/five_dimensions_report.json](../data/five_dimensions_report.json)。旧1000案、90%及云端接口要求已被本轮要求替代。
